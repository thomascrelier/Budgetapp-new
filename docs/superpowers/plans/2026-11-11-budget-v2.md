> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every number in the budget app consistent and correct, move bank imports into the app, and give the rental property a tenant ledger and a T776 tax view with Drive receipts.

**Architecture:** Pure logic lives in small modules under `budget-vercel/src/lib/` (row parsing, dates, classification, rules, import, rental ledger, T776, receipt matching), each unit-tested with vitest. `src/lib/sheets.js` stays the only Google Sheets I/O layer; API routes under `src/app/api/` are thin wrappers that load data, call the pure modules and return JSON. React components in `src/components/` render.

**Tech Stack:** Next.js 16 (app router), React 18, Tailwind 3, framer-motion, recharts, googleapis (Sheets v4 + Drive v3), papaparse, vitest (new, dev only).

### Task 5: Import core: parse bank files, detect account, plan new vs duplicate

**Files:**
- Create: `src/lib/import/parse.js`, `src/lib/import/detect.js`, `src/lib/import/plan.js`
- Test: `src/lib/__tests__/import.test.js`

**Interfaces:**
- Consumes: `parseAmount`, `parseDate` (Task 1), `categorize`, `accountKind`, `buildHistory` (Task 4).
- Produces:
  - `parseBankCsv(text: string): { format: 'cibc-account'|'cibc-card'|'header', rows: Array<{ line: number, date: string, description: string, amount: number, card?: string }>, errors: Array<{ line: number, reason: string }> }`. No-header detection: first cell of first non-empty line is a date. CIBC: columns date, description, debit, credit (+ card number for card files); `amount = credit − debit`. Header files: columns found case-insensitively among `date|transaction date|posted date`, `description|payee|merchant|details`, `amount|value` or `debit`/`credit` (either may be blank).
  - `detectAccount(rows, transactions, accounts): Array<{ account_id: number, name: string, matched: number, ratio: number }>` sorted by `matched` desc; count-aware matching on `(date, round2(amount))`.
  - `planImport(rows, accountTxns: Transaction[], opts: { kind, history, olderThanDays?: number }): { new: PlannedRow[], duplicates: PlannedRow[], older: PlannedRow[] }` where `PlannedRow = row & { category: string }`. Count-aware dedupe on `(date, round2(amount))`: if the account has N such rows, the first N file rows with that key are duplicates. Non-duplicates dated more than `olderThanDays` (default 7) before the account's latest date go to `older`.

**Interfaces:**
- Consumes: `Tenant` (Task 7), `addMonths`, `monthOf` (Task 2).
- Produces (`ledger.js`): `utilityBills(txns): Array<{ id, date, kind: 'electricity'|'gas'|'water', amount, due_month }>` (categories Electricity, Gas, Water with amount < 0; water `due_month = addMonths(monthOf(date), 1)`, others same month); `buildLedger({ txns, tenants, now }): Array<TenantLedger>` where `TenantLedger = { tenant, owed: number, credit: number, open: Array<{ label, bill_date, due_month, owed }>, months: Array<{ month, charges: Array<{ label, bill_date, amount, paid, status: 'paid'|'partial'|'open' }>, payments: Array<{ date, amount, utility_amount }> }> }`. Charges per tenant = `round2(bill.amount_abs × utility_share)`, only for `due_month` within the tenant's start/end. Labels: `"<Kind> (<Mon D> bill)"`, e.g. `Water (Jun 19 bill)`. Utility part of a payment: category Rental Income, description matches any `|`-separated `match_text` term (case-insensitive); `with_rent` → `max(0, amount − base_rent)`; `separate` → `amount` when `amount ≤ separate_max`, else 0. Allocation per algorithm below.
- Produces (route): `GET /api/rental/tenants` → `{ needs_setup: boolean, tenants: TenantLedger[] }` (rental-account transactions only); `POST /api/rental/tenants` body `Tenant` → saved tenant.

Allocation (not determined by the signatures):
```
ignore transactions dated after todayISO(now)
for each month in order:
  open = all charges with due_month <= month and remaining > 0, oldest bill_date first
  for each utility payment this month, in date order:
    if a subset of open charges has remaining summing to the payment within ±0.02:
      mark those charges paid in full and consume the whole payment (no 1-cent leftovers)
    else pay open charges oldest-first until the payment is used up
    any unused amount is added to credit
  then apply credit to open charges oldest-first
```
